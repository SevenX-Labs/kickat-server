# Customer Notifications API Specification

All customer in-app notification endpoints are served under `/api/v1/notifications`.

Notifications are automatically generated by the system for order status updates, payment events, and promotional campaigns created by the Admin dashboard.

---

## Endpoints Overview

| Method | Endpoint | Auth Required | Description |
| :--- | :--- | :--- | :--- |
| `GET` | `/api/v1/notifications` | Yes | Get paginated in-app notifications feed |
| `PATCH` | `/api/v1/notifications/read-all` | Yes | Mark all notifications as read |
| `PATCH` | `/api/v1/notifications/:id/read` | Yes | Mark single notification as read |

---

## Endpoint Details

### 1. Get Notifications Feed

Retrieve a paginated list of the authenticated user's in-app notifications, sorted by newest first. This includes transactional alerts (e.g., orders, refunds) and promotional campaign alerts.

- **Method:** `GET`
- **Route:** `/api/v1/notifications`
- **Authentication:** Required (Bearer Token)

**Query Parameters:**
| Field | Type | Description |
| :--- | :--- | :--- |
| `page` | Integer | Page number (default: 1) |
| `limit` | Integer | Items per page (default: 10) |

**Response (200 OK):**

  "items": [

      "updatedAt": "2026-09-12T10:00:00.000Z"
    },
    {

### 2. Mark All Notifications as Read

Mark all unread notifications for the authenticated user as read.

- **Method:** `PATCH`
- **Route:** `/api/v1/notifications/read-all`
- **Authentication:** Required (Bearer Token)

**Response (200 OK):**
```json
{
  "success": true,
  "message": "All notifications marked as read"
}
```

### 3. Mark Single Notification as Read

Mark a specific notification as read.

- **Method:** `PATCH`
- **Route:** `/api/v1/notifications/:id/read`
- **Authentication:** Required (Bearer Token)

**URL Parameters:**
- `id` (String) - The UUID of the notification.

**Response (200 OK):**
```json
{
  "success": true,
  "message": "Notification marked as read"
}
```
